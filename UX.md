# UX.md — Claude for creatives

What a new designer or writer on this project would need to be told. Read
with CLAUDE.md (the brief) and DESIGN.md (the tokens).

## Who this is for

One learner: an experienced creative director and content writer with UI/UX
background, strong at prompting AI tools, new to VS Code, the terminal and
Git. She reads on a laptop while working, and on a phone when reviewing.
She does not need the craft explained; she needs the tooling explained.

## What she is trying to do

Become able to design and run UI/UX and content workflows with Claude and
Claude Code for a small business, without first becoming a developer.

## What we know (research findings, Oct 2026)

- The designer's value is moving toward strategy, research, judgement and
  the context fed to AI tools (NN/g 2026). The tutorial therefore teaches
  context files and review before code.
- AI-generated screens default to generic unless the prompt is specific or
  a real reference is attached (NN/g prototyping tests). Every module that
  generates visuals asks for art direction and a reference.
- Adoption is high and trust is lower (Figma 2026). The rubric and the
  "evidence, not claims" habit exist to close that gap.
- Greek is a lower-resourced language for general models; no benchmark
  exists for English→Greek interface copy. Greek output always goes through
  a native reviewer.

## Interaction standards for the site

- One path: modules in order, previous/next at the bottom of each. The
  sidebar is for orientation, not for skipping ahead.
- Every module page has the same seven parts in the same order so the
  reader learns the shape once.
- Prompts are copyable with one click and readable without it.
- Checkpoints are testable statements, never feelings ("you understand…").
- Nothing on the site depends on JavaScript to be readable.
- Every page carries a "Last verified" date because the product facts change.

## Terminology

- "Claude app", "Claude Design", "Claude Code" — the three surfaces, named
  this way every time.
- "skill", "subagent", "hook", "plugin", "MCP" — lower case except MCP.
- "repository" on first use in a page, "repo" allowed after.
- "prompt" for what she types; "brief" for the document a prompt points at.
- British spelling (colour, organisation, localisation).

## Known constraints

- GitHub Pages serves the site under /repository-name/, so all links are
  relative.
- Google Fonts are loaded from the network; the fallbacks in DESIGN.md must
  look acceptable offline.
- Product names, plan contents and prices changed several times in 2026 and
  will again. Pages state facts with a date and link to the official source.
