Figma round-trip with MCP

Connect Figma to Claude Code so a frame becomes a coded page, and a coded page becomes editable frames on the canvas. Optional if you don't work in Figma; valuable if your clients do.

By the end of this module you can

  • Explain what MCP is and why it matters for designers in one paragraph.
  • Connect the Figma MCP server to Claude Code and implement a frame from it.
  • Send a coded interface back to Figma and continue exploring on the canvas.

MCP in one paragraph

MCP — the Model Context Protocol — is a standard way for Claude to connect to other tools. Instead of you copying things between apps, Claude can read from and write to them directly: a Figma file, a Notion workspace, GitHub. For design work the Figma connection is the important one, because it lets Claude read the real structure of a design — components, tokens, layout — rather than squinting at a screenshot, and NN/g's testing found that giving the model a real Figma frame produced the most faithful results.

Figma → Claude Code

In a Code session, click + under the prompt box and choose Add connectors (connectors are MCP servers with a sign-in flow). Find Figma, connect it, and sign in to Figma in the browser when asked. If Figma is not listed there, choose Add plugins instead and install the official Figma plugin, which brings the connection with it. Or ask Claude: "Connect the Figma MCP server to this project and walk me through signing in."

Figma recommends its remote server for the fullest feature set. Reading design context is reported to work on any Figma plan.

Prompt: implement a frame

Use the Figma MCP to read this frame: [paste link]. Implement it as a section of index.html using only our DESIGN.md tokens and existing components; where the frame uses a value we do not have, use the nearest token and tell me. Screenshot the result at 1440px, compare it to the frame, and list the differences.

Claude Code → Figma

Since February 2026, Figma's "Code to Canvas" lets Claude Code send a running interface into Figma as editable frames. Once connected, the instruction is simply "Send this to Figma". This direction needs the remote MCP server, and writing into an existing file needs a Figma Full seat with edit access. Early adopters reported the capability sometimes not appearing in a session; if that happens, reconnect Figma from + → connectors and try again before assuming it is unavailable.

Prompt: back to the canvas

Send the hero section we just built to Figma as a new page called "Hero — coded v1". Then tell me what came across as editable layers and what came across as flattened, so I know what I can change on the canvas.

When to go which way

  • Figma → code when the client's design is already in Figma and the job is faithful implementation.
  • Code → Figma when you explored quickly in Claude Design or Claude Code and now want to iterate visually, present to a client in the tool they know, or hand to another designer.
  • Neither for small sites you own end to end. Claude Design plus Claude Code is a complete loop; Figma adds a seat and a step.

Exercise: one section, both ways

  1. Connect Figma and confirm it is listed and signed in: ask Claude "Which connectors can you use in this session?"
  2. Pick a hero section in a Figma file you can edit. Run the implement-a-frame prompt. Judge the screenshot comparison yourself before reading Claude's list.
  3. Run the back-to-the-canvas prompt. In Figma, make two changes to the imported frames.
  4. Ask Claude to read the updated frame and reconcile the code with it. You have completed a round trip.

Checkpoint

  • The Figma MCP is connected and you have implemented one frame with tokens, not guessed values.
  • You have sent a coded section to Figma and edited it there.
  • You can say, for your own work, which direction you will use most and why.
