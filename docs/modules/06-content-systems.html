Content systems in Claude Code

Your voice skill moves into the codebase. A microcopy matrix generates every state; an editorial-QA helper checks it; a glossary-driven workflow handles Greek.

By the end of this module you can

  • Install your brand-voice skill in a Claude Code project so it applies to every line of copy.
  • Generate and review a complete set of interface states from a microcopy matrix.
  • Run an English→Greek localisation workflow with a glossary and a native-review gate.

The skill, in the repository

In Module 1 you wrote a brand-voice skill in the Claude app. In Claude Code a skill is a folder: .claude/skills/brand-voice/SKILL.md. The file starts with a name and a one-line description of when to apply it, then the rules. Claude loads it whenever copy is involved, or when you type /brand-voice. Because it lives in the repository, it is versioned, shared with anyone who clones the project, and improved by every correction you make.

The skill this site uses is on the Templates page. Copy its shape, not its content.

The microcopy matrix

Interface copy is a system, not a pile of strings. Write the system down once as a matrix and let Claude fill it:

StateToneLengthRule
SuccessBrief, warm≤ 8 wordsName what happened; no exclamation marks
ErrorCalm, directive≤ 20 wordsSay what went wrong and the next step; never blame, never apologise
EmptyInviting≤ 15 wordsOne action the person can take now
LoadingNeutral≤ 5 wordsSay what is loading
ConfirmationPlain≤ 25 wordsWhat will happen and what cannot be undone; button says the action, not "OK"

Save it as content/microcopy-matrix.md in the project and reference it from the skill. Two rules from Anthropic's own design guidance are worth adding: a button says exactly what will happen ("Save changes", not "Submit"), and an action keeps the same name all the way through — the button that says "Publish" produces a message that says "Published".

Prompt: every state of a form

Using the brand-voice skill and content/microcopy-matrix.md, write copy for every state of the contact form: field labels, helper text, the success message, three error types (empty required field, invalid email, server failure), and the empty state for the message history. Return it as a table with a character count per line. Flag any line where you had to choose between two rules in the skill.

An editorial-QA helper

A subagent is a specialist Claude Code can hand work to, with its own instructions and its own limits. An editorial-qa subagent that can only read files, never edit them, is a safe second pair of eyes: it checks terminology against the glossary, reading level, claims that need a source, length limits and the voice rules, and reports what it finds. You decide what changes.

Prompt: create the helper

Create a read-only subagent called editorial-qa in .claude/agents/. It reviews any text I point it at against the brand-voice skill, content/microcopy-matrix.md and content/glossary-el.md, and reports: terminology errors, lines over their length limit, claims that need a source, and reading level. It must not edit files. Then run it on docs/contact.html and show me the report.

Greek: draft with Claude, ship with a native reviewer

Two facts shape the workflow. Published research treats Greek as a lower-resourced language where general models lag behind their English performance, and no solid benchmark exists for English→Greek interface copy. So Claude is the drafter and transcreator, never the final authority. The workflow:

  1. Keep a content/glossary-el.md: every product term with its agreed Greek form, grammatical notes, and the forms to avoid.
  2. Add a Greek section to the brand-voice skill: formality (εσείς or εσύ), tone shifts, anything that does not translate.
  3. Ask Claude to translate and to flag every line where idiom or tone might not carry, proposing a transcreation.
  4. A native Greek reviewer signs off before anything is published. Build this as a stop in the workflow, not a hope.
Prompt: Greek pass

Translate the contact-form copy to Greek using content/glossary-el.md and the Greek rules in the brand-voice skill. Put English and Greek side by side. Flag every line where the tone or idiom may not carry over and offer a transcreation. Mark the file as awaiting native review; do not publish it.

Exercise: a complete contact form, in two languages

  1. Move your brand-voice skill into .claude/skills/brand-voice/SKILL.md in the studio-site project. Write the microcopy matrix and a starter glossary (ten terms is enough).
  2. Run the every-state prompt. Review each line against the matrix yourself first, then run the editorial-qa helper and compare its findings with yours.
  3. Run the Greek pass. Give the side-by-side to a native reviewer and record every correction in the glossary or the skill. The corrections are the valuable output.
  4. Commit the skill, matrix, glossary and copy. These four files are now a content system any project can inherit.

Checkpoint

  • The brand-voice skill lives in the repository and copy comes out on-brand without being asked.
  • The editorial-qa helper exists, cannot edit, and caught at least one thing you missed (or you caught one it missed — either way, you know the difference now).
  • The Greek copy has been through a native reviewer and the glossary has grown as a result.
