The loop

Anthropic describes Claude Code as an agent rather than a chatbot: it reads your files, runs commands, makes changes and works through a problem while you watch, redirect, or step away. In practice every task runs the same loop:

  1. Gather context. It reads CLAUDE.md, any skills that apply, and the files you point it at.
  2. Plan. It proposes what to change. In plan mode it stops here and waits for you.
  3. Act. It edits files and runs commands.
  4. Verify. It runs whatever check you gave it: a build, a test, a screenshot comparison.
  5. Report. It tells you what it did. You approve, redirect, or reject.

You are the director at steps 2 and 5. Everything in this module is about making those two moments count.

@filenamePoints Claude at a specific fileWhenever you mean a particular file; it saves Claude guessing.
Paste an imageGives Claude a screenshot or reference to look atAlways, for visual work. "Match this" beats any adjective.

Evidence, not claims

The single habit that separates good Claude Code sessions from frustrating ones: give Claude a way to check its own work, and ask to see the result. For a page, that means a screenshot at phone and desktop width compared against the design. For copy, it means the text printed back with its character count. Anthropic's own guidance is the same — give Claude a check it can run, and prefer a screenshot comparison for anything visual. "It should work now" is not evidence. A screenshot is.

Prompt: plan first

Read brief.md and the attached design screenshot. Propose a file structure and a build plan for a static HTML page using only the colours and type in the screenshot. List any decisions you would have to guess at and ask me about them. Do not write any code yet.

Prompt: build and verify

Build it. When done, start a local preview and give me the address. Then take screenshots at 390px and 1440px wide, compare both against the design screenshot, list every difference you can see, and fix them before telling me it is finished.

Prompt: interview me first

Before building the pricing page, interview me — one question at a time — until you have enough to write a one-page brief. Then show me the brief and wait for my approval.

Seeing the page

Ask Claude to start a local preview; it will run a small server and give you an address like http://localhost:3000 to open in your browser. Keep the browser and VS Code side by side. When you change something, reload. For plain HTML sites the VS Code "Live Preview" extension works too, and reloads automatically.

Exercise: from canvas to page

  1. Create a folder studio-site, open it in VS Code, start Claude Code and run /init.
  2. Export your Module 2 one-pager as an image and save it in the folder. Write a brief.md of ten lines: goal, audience, sections, call to action, tone.
  3. Switch to plan mode and run the plan-first prompt. Answer its questions. Read the plan: does the file structure make sense to you? If not, say so.
  4. Approve, then run the build-and-verify prompt. Open the preview. Compare it with the screenshot yourself before reading Claude's list of differences.
  5. Ask for three changes you would give a junior designer. Watch each diff in Source Control before approving. Commit when it is right.

Checkpoint

  • A page built by Claude Code opens in your browser and resembles your Claude Design concept.
  • You used plan mode, read a diff, and rejected or redirected at least one proposed change.
  • You have a screenshot Claude took as evidence, and you spotted at least one difference it missed. (You will. That is why you are the director.)
