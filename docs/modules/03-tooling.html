Module 3 of 9

Your studio in the desktop app

Claude Code runs inside the Claude desktop app you already use, in its Code tab. No code editor, no terminal window. This module sets it up and teaches the handful of Git words you need to direct it.

By the end of this module you can

  • Open a Code session in the Claude desktop app on a folder of your own.
  • Explain a repository, a commit, a push, a branch and a pull request in one sentence each.
  • Get your first project onto GitHub, with Claude doing all the typing.

One app, two kinds of conversation

The Claude desktop app has a Chat side, where you have worked in Modules 0–2, and a Code tab. A conversation in the Code tab is called a session, and each one is attached to a folder on your computer. In a session Claude can read and change the files in that folder, run commands, preview your page, and save versions to GitHub. You watch and approve; Claude does the typing.

Three panels matter, and you will meet them all in the exercise:

  • The prompt box — where you brief Claude. Under it are the folder control and the mode selector.
  • Changes — every edit Claude has made, line by line, with before and after. You can comment on any line, like marking up a proof.
  • Browser — a preview of your page inside the app. Claude opens it, takes screenshots and checks its own work there. Open it yourself with Cmd/Ctrl+Shift+B.

The Git words, and nothing more

Git keeps the history of a project — every saved snapshot, who made it, and why. GitHub is where that history is stored online and where your site is published from. If you have used version history in Figma or Google Docs, you already understand the purpose. The vocabulary is the only new part:

WordMeaningDesign-world equivalent
Repository (repo)The project folder plus its full historyThe project file, with every version kept
CommitA saved snapshot with a message saying what changed"Save version: hero copy revised"
PushUpload your commits to GitHubSyncing to the shared drive
BranchA parallel copy for trying something without touching the main versionDuplicating a page to explore a direction
Pull requestA proposal to merge a branch into the main version, with a place to review itPresenting a direction for approval
DiffThe exact before-and-after of a change; what the Changes panel showsComparing two versions side by side

Setting up

  1. Confirm your Claude plan is Pro or higher. Claude Code is not available on the Free plan.
  2. Install or update the Claude desktop app from claude.com/download and sign in. Click the Code tab.
  3. Create a folder on your computer called hello-studio, somewhere you will find it again (Documents is fine).
  4. In the Code tab, before you type anything, click the folder control in the row under the prompt box and choose hello-studio.
  5. Find the mode selector next to it and set it to Manual. Claude will ask before every edit and every command. You will relax this later, once you trust a workflow.
  6. Create a free account at github.com.
  7. Install the GitHub CLI from cli.github.com — it is an ordinary installer, like any app. It is the piece that lets Claude create repositories and publish for you. You will never open it yourself.
  8. If the app tells you it needs Git, follow the link it gives. On Windows that means installing Git for Windows from git-scm.com; on a Mac, accept the offer to install the developer tools.

The desktop app changes often. If a button here does not match what you see, the official desktop guide is current; this page is not guaranteed to be.

Let Claude narrate

You do not have to learn commands. You have to be able to follow what is happening. In Manual mode Claude shows you every command before it runs; ask it to explain each one in plain language, and you will pick up the shape of things quickly.

Prompt: connect to GitHub

I am a designer and this is my first Code session. Explain every command in one plain sentence before you run it. First, check that Git and the GitHub CLI are installed. Then sign me in to GitHub without asking me any questions in a terminal: run gh auth login --web --hostname github.com --git-protocol https, tell me the one-time code and the web address to open, and wait while I approve it in my browser.

Prompt: first repository

Now, in this folder: start a Git repository, create a README.md that says what this project is, make the first commit with a clear message, create a private GitHub repository called hello-studio, and push to it. Tell me the repository's web address when you are done.

Prompt: understanding what happened

Show me the commit history as a short list. Then explain what a branch is using this repository as the example, and create one called try-new-headline. Do not change any files yet.

Exercise: hello studio

  1. Complete the setup list. Take your time; this is the only module where the obstacles are mechanical rather than creative.
  2. Run the connect-to-GitHub prompt. Claude gives you a short code and a web address (github.com/login/device). Open the address in your browser if it does not open by itself, enter the code and approve. If Claude ever says you need to type something in a terminal, reply "do it for me another way" — there almost always is one. Approve each command Claude asks to run, reading its explanation first.
  3. Run the first-repository prompt. When a sentence does not make sense, ask Claude to rephrase it before you approve the next step.
  4. Open your repository on github.com and find the README. Your file is now stored online, visible only to you. Publishing a site later uses the same mechanism with better content.
  5. Ask Claude to change one word in the README. Open Changes and look at the diff before you say "commit and push". Leave a comment on the line to see how it works.
  6. Run the understanding-what-happened prompt. When you have read its explanation, ask Claude to switch back to the main branch.

Checkpoint

  • A Code session opens on your folder, in Manual mode, and Claude can see the files in it.
  • A private repository exists on GitHub with at least two commits.
  • You have read a diff in the Changes panel and can explain commit, push and branch without looking at the table.
