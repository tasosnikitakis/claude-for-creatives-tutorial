# Project
Tutorial site "Claude for creatives": static HTML in docs/, published with
GitHub Pages from the main branch and the /docs folder. No build step.
The repository is itself the worked example the tutorial teaches: keep
CLAUDE.md, DESIGN.md, UX.md, the brand-voice skill and the ux-reviewer
subagent consistent with what the module pages say.

# Commands
- Preview: `npx serve docs` (or ask Claude to open docs/index.html in the desktop app's Browser pane)
- Check:   `npx html-validate "docs/**/*.html"`

# Design rules
- IMPORTANT: use tokens from @DESIGN.md only; never invent colour, type or spacing values. The CSS variables in docs/assets/style.css mirror DESIGN.md — change DESIGN.md first.
- IMPORTANT: all copy follows the brand-voice skill. Sentence case. No exclamation marks.
- IMPORTANT: every page works at 390px and 1440px; every image has meaningful alt text; contrast meets WCAG AA.
- Links inside the site are relative (assets/style.css, ../index.html), never absolute, because GitHub Pages serves the site under a repository path.
- Keep one memorable element per page (the prompt panels); everything else quiet.
- Module pages share one structure: kicker, h1, lede, objectives, lesson, prompts, exercise, checkpoint, pager, "last verified" line.
- Navigation and prev/next links are generated by docs/assets/site.js from its MODULES list. To add or rename a module, edit that list and the module-list on docs/index.html.

# Art direction
Warm and calm, close in feel to the Claude apps she works in: warm paper,
near-black ink, one clay accent for links and prompt panels only. Source Serif 4
for headings and reading text, Source Sans 3 for navigation, labels and tables.
Left-aligned. No cards-for-everything, no gradients, no all-caps labels, no
arrows on links. Never use Anthropic's logos, the Claude mark, wordmarks or
proprietary typefaces; the site is independent and says so on the start page.

# Workflow
- Plan before changes that touch more than one file.
- Show screenshots as evidence before saying a visual change is done.
- Run the ux-reviewer subagent on any new or changed page before committing.
- Every page ends with a "Last verified <date>" line; update it when the page's facts are checked.
- Commit after each approved change with a message that says what changed and why.
